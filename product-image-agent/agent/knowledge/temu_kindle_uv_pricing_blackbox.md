# TEMU Kindle UV 核价反向推导与黑盒实验系统 V1.0

## 0. 文档定位

本知识库用于建立一套面向 TEMU 全托管/核价场景的商品实验体系。

核心业务模型：

> 低价白胚 → UV加工 → 定制差异化 → 场景结合 → 独立商品结构 → 1胚N卖 → 黑盒核价实验 → 影子核价模型

本系统不假设已知 TEMU 内部核价算法源码，也不声称掌握官方未公开的内部权重。

核心方法是：

> 将 TEMU 核价系统视为黑盒，通过受控变量实验，持续记录“商品输入变化 → 核价输出变化”，逐步反推出高敏感变量、低敏感变量、变量组合效应和可复制的高核价结构。

# 1. 核心思想

## 1.1 真正的问题

对于 Kindle UV 定制商品，卖家视角通常是：

- 原创图案
- 姓名定制
- 宠物定制
- 出生花
- 星座
- 情侣纪念
- 礼物场景

但平台模型可能首先识别：

- Kindle 壳轮廓
- 翻盖结构
- 开孔
- TPU/PC 边框
- 尺寸
- 型号适配
- 胚体结构
- 相似白胚
- 相似低价商品

因此必须始终问：

> 把 UV 图案移除以后，这个商品在机器视角里还剩下多少独立价值？

---

## 1.2 反向实现的定义

反向实现不是：

- 猜平台源码
- 伪造商品
- 虚构套装
- 审核时与发货时不一致
- 隐藏低价 SKU
- 通过欺骗方式规避规则

反向实现是：

> 用真实可交付商品做黑盒实验，观察不同真实变量对核价结果的影响。

---

## 1.3 核心循环

```text

```

# 3. 1胚6卖的正确理解

## 3.1 错误结构

同一个 Kindle 白胚，仅改变：

- 红色
- 蓝色
- 花朵
- 宠物
- 条纹
- 字体

这种更接近：

> 1胚6图

而不是：

> 1胚6商品

---

## 3.2 正确结构

同一个白胚，拆成 6 个不同购买理由：

| 商品身份 | 核心购买理由 |
|---|---|
| Identity Case | 身份表达 |
| Pet Reader Case | 宠物陪伴 |
| Birth Flower Library | 出生月份与个人身份 |
| Couple Reading Case | 情侣纪念 |
| Book Club Case | 社群归属 |
| Gift Message Case | 礼物情绪 |

这才是：

> 一胚多商品身份模型

英文可记为：

> One Blank, Multiple Product Identities

# 4. 黑盒实验的输出变量 Y

不要只记录“核价多少钱”。

至少记录以下输出：

| 输出变量 | 符号 | 说明 |
|---|---|---|
| 最终核价值 | P | TEMU 最终核价 |
| 核价率 | R | 最终核价 ÷ 申报价 |
| 毛利空间 | M | 最终核价 - 总成本 |
| 是否通过 | A | 通过=1，不通过=0 |
| 核价耗时 | H | 提交到结果的时间 |

---

## 4.1 核价率公式

```text
R = Temu最终核价值 ÷ 申报价
```

例如：

```text
申报价 = ¥30
TEMU核价 = ¥18

R = 18 ÷ 30 = 0.60
```

即：

> 核价保留率 60%

---

## 4.2 为什么核价率比绝对价格重要

两个商品：

### 商品 A

```text
申报价：¥30
核价：¥15
核价率：50%
```

### 商品 B

```text
申报价：¥30
核价：¥22
核价率：73.3%
```

B 可能触发了更强的价值特征。

# 11. 核价杠杆公式

核心目标不是：

> 哪个设计最漂亮？

而是：

> 哪个新增成本能够带来最高核价提升？

定义：

```text
核价杠杆 L
=
核价提升金额
÷
新增真实成本
```

例如：

```text
新增成本 = ¥1.1
核价提升 = ¥8
```

则：

```text
L = 8 ÷ 1.1 ≈ 7.27
```

即：

> 每增加 ¥1 成本，换来约 ¥7.27 核价提升。

# 21. 核价分析标准问题

每次核价后必须回答：

```text
1. 为什么这个商品核价高？
2. 为什么这个商品核价低？
3. 是商品身份影响吗？
4. 是主图影响吗？
5. 是标题语义影响吗？
6. 是定制深度影响吗？
7. 是场景影响吗？
8. 是真实交付结构影响吗？
9. 是市场低价同款密度影响吗？
10. 是否存在变量组合效应？
11. 下一轮只需要改变哪个变量？
12. 这个结果是否完成复验？
```

---

# 22. 测试纪律

## 22.1 一次只改少量变量

否则无法判断因果。

---

## 22.2 同一轮尽量保持

- 相同白胚
- 相同型号
- 相近申报价
- 相近提交周期
- 相近图片质量
- 相近 SKU 数量

---

## 22.3 每个结论至少复验

推荐：

```text
单次出现 = 假设
两次重复 = 强假设
三次以上稳定 = 初步规则
跨胚体稳定 = 可复制规则
```

---

# 23. 禁止事项

严禁：

- 核价商品与实际发货商品不一致
- 虚构赠品
- 虚构套装
- 虚构材质
- 虚报数量
- 隐藏低价 SKU
- 审核时 A、发货时 B
- 通过误导图片制造不存在的交付价值
- 用无关关键词伪造商品身份

本系统仅用于：

> 真实商品差异化与真实可交付商品结构优化。

# 26. Agent 调用规则

当知识库 Agent 接收到以下问题：

- 为什么核价低？
- 这个 Kindle 壳怎么提高核价？
- 同胚如何做差异化？
- 1胚6卖怎么拆？
- 下一个实验怎么做？
- 哪个变量最值得测试？
- 如何设计核价对照组？

应执行：

```text
Step 1：识别当前白胚
Step 2：判断商品身份
Step 3：评估10个核心变量
Step 4：检查是否仅为换图
Step 5：执行去图案测试
Step 6：判断低价同款密度
Step 7：选择1-3个实验变量
Step 8：生成对照组
Step 9：给出记录字段
Step 10：核价后分析差值
Step 11：形成下一轮实验
Step 12：写入核价数据库
```

# 28. 核心结论

真正高级的“1胚6卖”不是：

> 一个壳换 6 个图案

而是：

> 一个低成本标准白胚，创造 6 个不同商品身份、6 个不同购买理由、6 套不同定制机制、6 套不同场景和价值证据。

最终通过：

> 黑盒实验 + 数据记录 + 变量复验 + 影子核价模型

形成自己的：

# TEMU 核价知识库与决策系统
